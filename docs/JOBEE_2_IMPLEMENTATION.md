## JOB-P1-T01 — Three-section platform adaptation

**Scope:** Reuse the existing platform and migrate navigation to Explore, Applications and Profile. No schema, API contract, model-provider, dependency or production infrastructure changes.

**Delivered:** Explore is the default authenticated workspace. Applications retains tracking, review, messages, interviews and contextual preparation. Profile contains candidate editors, CV/documents, saved answers, preferences, appearance, account connections, advanced settings and activity. Home and Settings are retired as primary destinations; old section callbacks and notification record targets remain compatible. Existing submission authorization is unchanged.

**Session/accessibility:** Private views wait for the session and are remounted for the active user. Signed-out users see a welcome/sign-in path. Private notification polling is gated by identity; notification/invitation dialogs have distinct per-user keys. Mobile Escape/close returns focus after the workspace ceases to be inert, and selecting a destination closes the drawer and focuses main content. Existing focus traps and invitation deep links remain covered.

**Platform correction:** The Vite development proxy now preserves `/api`. Stripping it caused the newer `/api/job-search/settings` endpoint to return 404 even though older dual-mounted routes worked. Browser regression coverage explicitly checks this endpoint and the absence of initial Explore alerts.

**Verification:** 635 unit/integration tests across 72 files; 32 Chromium E2E scenarios passed against an isolated local UI database. Browser coverage includes both themes, mobile navigation, document formats and access failures, profile editing, application records, review/consent safeguards, and a second user's access denial. Explore and Profile renders were visually inspected. The obsolete Home pixel-reference scenario was replaced with Explore theme/navigation/overflow checks and screenshot capture; old Home reference files remain historical, and no new cross-platform pixel baseline is claimed. Final eight-gate results are recorded in TASK_LOG.md before checkpointing.

**Preservation and limits:** No existing records or documents were migrated/deleted, no application was submitted, no account was connected, and no production or paid operation occurred. The existing preparation/review journey stays until JOB-P3-T01/JOB-P5-T01 introduce the shared authorized engine. This task does not claim One-click Apply or Autopilot completion. Backend auth and tenant protections remain in place.

**Next dependency:** JOB-P1-T02 — close verified candidate context and preferences gaps using existing data structures; no new official microtask identifiers.

## JOB-P1-T02 — Verified candidate context and unified Profile

**Scope:** Complete missing preference persistence and candidate-facing controls using existing tables; make reusable answers trustworthy at generation and submission time. Candidate import, CV management, facts/provenance, personal and professional editors and integrations remain reused rather than rebuilt.

**Frontend:** Profile preferences include employment type, seniority, confirmed work-authorization countries, internship eligibility, availability, preferred languages, unpaid-position preference and maximum salary. Empty eligibility stays unknown; work arrangement is not preselected for a new profile. Existing saved currencies remain selectable. Ordinary search preferences precede collapsed existing application permissions, with clear separation from future Jobee 2.0 Autopilot. A failed preferences load shows a retry and prevents overwriting server values with defaults. Saved Answers exposes independent verification status and an explicit accuracy confirmation; editing the question or answer clears that confirmation.

**Backend/data:** The normal validated preferences API now persists existing workAuthorizationCountries, internshipEligible and availability columns on first creation and later updates. Partial changes preserve unrelated fields and explicit null/empty values; all reads/writes remain user scoped and audited. No new table or migration. Answer edits lose verification unless the request explicitly reconfirms it.

**Grounding and permissions:** Automatic library reuse requires a verified answer to the same normalized question, AUTO tier, no sensitivity and no unevaluated conditions. Category-only, substring and negated-question matches cannot select unrelated claims. Conflicting or MANUAL entries require input. Sensitive, scoped and REVIEW answers require review. Submission manifests revalidate only library entries actually used: owner, verification, exact prompt/content, source update time and any required question-specific human approval. Revoked or changed sources block existing submission tickets; changes to unrelated library entries do not invalidate other packages. This does not introduce broader submission permission.

**Verification:** All eight mandatory gates pass; lint has 0 errors and 693 existing warnings. 653 tests / 73 files pass, including preference creation/patch/clear/validation, audit and isolation; explicit verification invalidation; engine answer-reuse boundaries; and revoked-source submission authorization. All 35 Chromium scenarios pass. After visual review, four affected browser scenarios were rerun successfully against the final two-column desktop/one-column mobile layout, followed by a focused mobile drawer-inert/eligibility persistence check. New coverage includes preferences persistence without enabling submission, outage/retry protection and explicit answer verification. Two themes and mobile renders were inspected. Database gates use isolated local fixtures only. See TASK_LOG.md for the verification record.

**Limits/next dependency:** Broader country-specific matching behavior is part of JOB-P2-T02. Automatic preparation and unfamiliar ATS questions remain JOB-P3-T01/JOB-P5-T01; versioned Autopilot permission remains JOB-P5-T02. Complex saved-answer conditions are retained but require review; no new rules language is introduced. Real candidate verification is a user action; existing unverified data was not promoted. Prepared applications that depend on a changed/revoked saved answer may require regeneration; history and materials remain intact. No new AI provider/model, dependency, migration, real application, production deployment or paid operation was introduced. Next dependency: JOB-P2-T01 Explore/discovery adaptation, then JOB-P2-T02 matching convergence.

## JOB-P2-T02 — Shared grounded matching (2026-10-20)

Verified local source checkpoint: `6b5b07b236e3e4c9056616d65d34115dc02eb719`; Explore checkpoint: `616b990`. Subsequent checkpoint records change documentation only. No push, merge or deployment.

Implemented and verified locally: the existing matching/context/evidence/scoring and injected provider adapters now live in the existing shared backend workspace (`@job-agent/database/matching`). API compatibility exports preserve callers; the worker uses the same engine and consumes current MATCH records for draft preparation instead of inventing MATCHED/SKIPPED job states from exclusion-only checks. Manual/batch/daily/worker paths share eligibility and current inputs. Batch selection finds unseen/stale jobs beyond the old first-page window. Stable fingerprints ignore check-only timestamps and requirement row order, include material posting content and candidate/policy context, and invalidate algorithm 1.0 results. Explore ranking and worker selection revalidate freshness and revoke preliminary eligibility on stale results; old analyses remain preserved.

Policy: explicit remote/workplace restrictions cannot be bypassed by relocation. Country-specific authorization is explicit; remote/residence/no sponsorship cannot prove citizenship or global work rights. Unknown citizenship/clearance, jurisdiction and internship eligibility request review; confirmed exclusions remain blockers. Migration 0024 introduces nullable salary pay period with validation and a database constraint. Existing salary amounts keep unknown units. Currency/period mismatches do not generate fictional salary blockers or scores. AI receives only verified permitted evidence; the service revalidates returned IDs, cannot use semantic guesses to resolve sensitive requirements, and derives user explanations from grounded evaluations rather than publishing arbitrary model claims. Poor professional relevance has its own label. Match scores never authorize submission.

Explore defaults to fit ranking, exposes the match explanation and a material blocker/unknown in the result/detail context, and retains the full analysis tab. Existing views, IDs, source snapshots, documents, application records and security boundaries remain. No new service, queue, provider, paid call or production operation was introduced. The existing Zod library is explicitly declared where its validator moved.

Remaining dependencies: JOB-P3-T01 must establish durable job-scoped application intent before preparation, automatically prepare routine materials and pause only for material unknowns. JOB-P5-T01 must prove the provider workflow. The legacy worker discovery and draft-only preparation remain for later convergence into that proven pipeline; their presence does not claim complete One-click Apply or Autopilot. Existing AI model identifiers/adapters are preserved; paid/live model availability was not re-certified in this local fixture delivery.
