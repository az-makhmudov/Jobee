## Current behavior

Discovery rejects known location/seniority conflicts before spending its result limit, using the same compatibility rules as Explore. Explore sends `relevantOnly` through the actual HTTP client and applies profile compatibility, deterministic blockers and current SKIP decisions before pagination. Junior/Entry and Intern/Internship labels are normalized; known seniority conflicts cannot be rescued by a skills score. Unknown eligibility remains unknown. Algorithm 2.1.0 makes earlier analyses stale. Explicit library tools/history remain available; no owner candidate data was changed.

The main path is Profile → Explore → job details → Apply → Applications. Bulk/source tools, feedback buttons, job corrections and detailed fit/source tabs are progressive disclosures; technical unknown/state/provider labels are removed from the default job header. Existing applications use an exact owned job lookup, including older records, and retain a primary View application action. Application tracker/review remain visible; global communication tools are contextual. Unsupported employer forms now show an immediate employer-site handoff after a successful existing-attempt check. Supported hosted forms retain Quick Apply; no automatic success is implied. Material, consent, duplicate and uncertain-outcome checks remain intact.

Gemini is server-managed. Users cannot switch provider/model or trigger connectivity charges; legacy per-user overrides are ignored. Explicit disabled mode remains for offline verification. Ordinary accounts have 10 SUBMIT reservations per UTC day, including queued/failed attempts; admins and explicitly designated testers are exempt from that platform cap. Accepted Autopilot bounds remain independent. Tester invitation redemption/role assignment are atomic, and submitted role escalation is rejected.

All users may save up to 10 candidate documents. Vault and profile-import upload admission serialize on the same user row before storage; concurrent uploads cannot exceed the cap. Import document/session/master changes commit together, with file cleanup on failure. Existing excess documents are preserved, with further uploads blocked until reduced. Preview/deletion and submitted-artifact provenance remain available. **Self-service account deletion is not implemented**; JOB-P1-T02 will implement the owner-selected seven-day cancellation window followed by deletion of all Jobee-held data; export is optional.

Calendar OAuth consumes signed scope-bound state once and returns to configured `WEB_ORIGIN`, with success/refusal/failure feedback instead of account JSON. Availability/event-management separation and explicit write confirmation remain. Earlier read-only email, transactional enrichment/review and uncertain calendar-booking safeguards are retained.
