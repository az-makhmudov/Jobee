## Implementation and verification evidence

- Every mapped component now uses shared controls/cards, local typography/assets and semantic theme values. Existing handlers, record IDs, API payloads and status constants remain in their original components.
- `scripts/audit-ui-contracts.mjs` compares all 184 existing API calls and payloads in the 25 components with the audited baseline. Domain services, shared types, worker code and database schemas have no migration diff.
- G01/G02/G03/G13: browser tests exercise notifications/preferences, admin invitation controls, analytics, Smart Import entry, and all eight direct profile editors in shared dialogs; existing route and Smart Import tests retain decision/acceptance checks.
- G04/G05/G06: CRM board/list and application detail browser checks cover the original forms, required labels, native validation, note save, cancellation and navigation. Existing state-machine/CRM tests cover the 17 lifecycle statuses and reasoned corrections.
- G07: submission cancellation is verified without requesting an authorization ticket or starting a run. Existing browser-worker route/authorization tests cover tickets, the eight statuses, audit trace and uncertain results. Live ATS submission is excluded from preview validation.
- G08/G09: Studio tabs and unresolved readiness blockers render from live synthetic packages; edit-and-approve cancellation preserves other blockers. Existing package and data-integrity tests cover mixed pending/rejected/reconfirmation decisions and overrides independently.
- G10/G11: interview, debrief, availability and calendar-account controls are exercised in the local browser. Calendar/provider integration tests use the existing offline fixtures.
- G12/G14/G15/G16/G17: Jobs tabs/add/edit/archive cancellation, Messages, configuration/activity, guest sign-in/invitation, answers/preferences and Career Intelligence are covered through browser renders plus the existing route/component tests. Configuration/provider connections remain authoritative server states.
- G18: synthetic student examples exist only in the explicitly guarded local fixture seeder. Real names, totals, scores and records come from API responses. No Figma example is embedded as a production candidate fact.
- The approved preview addition uses the existing authenticated document-download route, Blob retrieval, locally packaged PDF resources, a sandboxed DOCX document and plain TXT. Browser checks cover rendering, zoom/close, access denial, damaged PDF, retry and rapid selection changes.

Full verification results and practical limits are recorded in `UI_MIGRATION.md`. Browser screenshots are generated under `output/playwright/`, which is deliberately ignored by Git.
